# Keychain (Secure Enclave SSH keys) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Named ECDSA P-256 keys created in the Mac's Secure Enclave, stored as an encrypted blob in the vault, chosen per host, and used by the hub to sign SSH authentication through the Swift helper. A Keychain view in the app manages them.

**Architecture:**
- The Swift helper `sshgate-touchid` gains `key-create` and `key-sign`.
- A new root-module package, `internal/sekey`, runs it and adapts it to `ssh.Signer`.
- `internal/config` stores `Keys` (with `EncBlob` per key) and `Server.KeyName`.
- `Resolve` decrypts the blob into `DialConfig`, and `sshx.authMethods` signs through `sekey`.
- The hub adds `keys.*` UI-door methods (protocol 14) and a `--keyHelper` flag, which the app passes.

**Tech Stack:** Go (golang.org/x/crypto/ssh), Swift CryptoKit (`SecureEnclave.P256.Signing`), mygo `ui`.

**Spec:** `docs/superpowers/specs/2026-11-17-keychain-design.md` (approved 2026-11-17)

**Branch:** `feat/keychain`, stacked on `feat/app-redesign-screens` (PR #58).

## Global Constraints

- **The key blob** (`dataRepresentation`, plaintext or base64) never reaches a UI-door reply, an MCP-door reply, an audit record, a log or stderr line, an error string, a command-line argument or the clipboard. It travels only from the vault to the hub's memory to the helper's stdin.
- **The vault's `Version` is not bumped.** It is in every secret's AAD. The new fields are `omitempty`, so a file without keys marshals byte-identically to today.
- **Blob encryption:** `config.Encrypt(masterKey, "keychain/"+Name+"/blob", aad, blob)` with `aad = strconv.Itoa(f.Version)+"|keychain|"+Name+"|"+PublicKey`.
- **Key names:** 1–64 bytes, matching `^[A-Za-z0-9._-]+$`, unique in the file. `Type` is always `"se-p256"`.
- **The new auth value is `"keychain"`.** Any auth other than `keychain` clears `KeyName`, as any auth other than `key` clears `KeyPath`.
- **Helper exit codes:** 0 ok, 1 other, 3 the key no longer works on this Mac, 5 Secure Enclave unavailable. The key commands never call `available()`, which requires biometrics.
- **Secure Enclave access control:** `SecAccessControlCreateWithFlags(nil, kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly, [.privateKeyUsage], nil)`, with no biometry.
- **Hard lock:** no new resolve of a Keychain host succeeds. Work resolved before the lock may still sign (the spec's Anti-goals, chosen by the author). Under soft lock, only hosts with a live grant resolve, as today.
- **AI clients:** the MCP door gets nothing new. `keys.*` exists on the UI door only. The app never calls `keys.list` from a timer, an animation or a redraw (idle lock).
- **UI-door rules:** strict params (`strictParams`), refused while locked, and each write goes through `config.Update` under `h.mu` (`writeKeyLocked`). Protocol is 14 (`ProtocolVersion` in `internal/hub/idle.go`, and in `app/hubapi`).
- **App rules:**
  - Keychain Delete is a `decisionButton(..., toneDangerFill)` with the 500 ms delay.
  - Cancel is the filled primary and has the focus.
  - Delete is disabled while the key is in use.
  - The app uses tokens only, with no copy change to existing screens.
- **Tests:**
  - root module: `go test -race ./...`;
  - app: `cd app && MYGO_GHOSTTY_VT=$PWD/build/natives/libghostty-vt.dylib go test -race -timeout 20m ./...` (~13 min);
  - `go vet` and `gofmt` clean in both modules.
- **Commits** end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; no session URL.

## Review Focus

1. **A vault file copied from another Mac, or a Secure Enclave reset:** the helper exits 3. The host fails with "this Secure Enclave key does not work on this Mac", never a raw helper error, and the hub keeps running. Test in Task 3.
2. **Deleting a key that a host uses** (`keys.delete` racing a `servers.save` that picks it): refused with `ErrKeyInUse`. Both run under `h.mu`, so a test of the sequential case suffices. Test in Task 4.
3. **Renaming a host whose auth is `keychain`:** `KeyName` survives the rename (it is not a secret and has no AAD), and the grant ends as for any rename. Test in Task 2.
4. **The blob leaking through an error:** a decrypt or helper failure must not quote stdin or the blob. Test in Task 4: search every reply and audit line for the base64.
5. **`keys.create` with a name already taken, or with an invalid name:** refused before the helper runs, so no orphan Secure Enclave key is made. Test in Task 4.

### Task 1: Helper commands and `internal/sekey`

**Files:**
- Modify: `app/native/touchid/main.swift`, `app/scripts/build-touchid.sh` (only if needed)
- Create: `internal/sekey/sekey.go`, `internal/sekey/sekey_test.go`, `internal/sekey/fakehelper/main.go`, `internal/sekey/sekeytest/sekeytest.go`, `internal/sekey/live_test.go`

**Interfaces:**
- Produces (package `sekey`, root module):
  - `func Create(ctx context.Context, helper string) (blob []byte, pub *ecdsa.PublicKey, err error)`
  - `func Sign(ctx context.Context, helper string, blob, data []byte) (r, s *big.Int, err error)`
  - `func NewSigner(helper string, blob []byte, pub ssh.PublicKey) ssh.Signer`: `Sign(rand, data)` runs `Sign` with a 10 s timeout and returns `*ssh.Signature{Format: "ecdsa-sha2-nistp256", Blob: ssh.Marshal(struct{R, S *big.Int}{r, s})}`.
  - `var ErrWrongMac` (exit 3) and `var ErrUnavailable` (exit 5). Other failures return a fixed generic error. stderr is never included in errors.
  - `func AuthorizedKey(pub *ecdsa.PublicKey, comment string) string`: the `ecdsa-sha2-nistp256 AAAA… comment` line.
- Helper contract:
  - `key-create`: no stdin; stdout `{"v":1,"blob":b64,"pub":b64(x9.63)}`.
  - `key-sign`: stdin `{"blob":b64,"data":b64}`; stdout `{"sig":b64(raw r||s, 64 bytes)}`.
- `fakehelper`: the same contract, using a software P-256 key. Its blob is the key's PKCS#8 DER. A `FAKE_EXIT` env var makes it exit with that code. A `FAKE_MARKER=<path>` env var makes it create that file whenever it runs.
- `package sekeytest`: `func Build(t testing.TB) string` builds `fakehelper` once per test binary (`sync.Once`, into a temp dir) and returns its path. The tests in Tasks 1, 3 and 4 all use it.

  - `TestSignerDialsSSHTest`: dial an `internal/sshx/sshtest` server with `ssh.PublicKeys(signer)`; the session runs `echo ok`. x/crypto's server verifies the signature before it calls `PublicKeyCallback`.

  - The blob goes on stdin only. The context deadline kills the helper.

**Interfaces:**
- Produces, on the UI door:
  - `keys.list {}` returns `[{name, type, publicKey, created, usedBy: [string]}]`.
  - `keys.create {name}` returns `{name, type, publicKey, created}` and writes an audit record `{kind: "config", action: "keyCreate", key}`.
  - `keys.delete {name}` returns `{}` and writes an audit record `{action: "keyDelete", key}`.
  - All three: `ErrLocked` while locked, and strict params.
  - `keys.create` checks the lock state, then validates the name (`config.ValidKeyName` and uniqueness), all **before** running the helper. It holds `h.mu` only around the `config.Update`, not across the helper exec. It re-checks uniqueness in the update, and on a lost race returns `ErrKeyExists`. The Secure Enclave key it made is then dropped; such a key cannot be used without its blob, which is acceptable.
- `hubproc.LaunchFor` gains a `keyHelper string` parameter. When it is non-empty, it appends `--keyHelper=<path>` to the args. The app passes the same path `touchid.HelperPath` resolves.
