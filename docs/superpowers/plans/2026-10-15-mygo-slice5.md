# mygo desktop, slice 5 (Tunnels) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The native mygo app runs SSH tunnels the way the Electron app does:
- a **Tunnels tab** per host, opened from the host card's Tunnels button (one per host, as Electron's `findKind`), listing the host's saved tunnels with their label, forward, status, connections, and Start or Stop, Edit and Delete;
- the **Add tunnel** and **Edit tunnel** dialog (Local, Remote, Dynamic; listen port, target host and port, label), checked as `parseTunnelForm` checks it, with the hub's refusals shown in the dialog;
- the host card's **running badge** (`N ⇄`); tunnels that outlive their tab and a lock, whose rows show the hub's state again after the unlock; a hub stop that ends them;
- the **Auto-allow dialog's warning** about the host's running remote tunnels, in the Enable delay's change key (the debt of slice 3b's Decision 2);
- the e2e spec `tunnels` ported as Go flow tests against a real `sshgate hub` and `sshtestd`, and `live-tunnels` as an opt-in test against a real host.

**Architecture:**
- **Layers.** Unchanged: `hubapi` (typed door calls and notifications), `model` (pure rules, their vitest cases as Go table tests), `view` (the `App` controller and its screens), `internal/hubtest`.
- **State.** The hub's tunnel list is one slice on `App` (`App.tunnels`, every server's), read with `tunnels.list` and kept current by `tunnels.state`; the states that land while a `tunnels.list` is in flight are buffered and replayed onto its reply (`App.tunnelBufs`, Electron's `tunnelBuffers`). A Tunnels tab is a `model.Tab` of kind `tunnels` plus a `tunnelsTab` on `App` (its server, its error line, its dialog), by tab id; its rows are `App.tunnels` filtered by server.
- **Dialogs.** Add and Edit tunnel are one `ui.Modal`; nothing in it is a consent action, so it has no guard.

**Tech Stack:** Go 1.27.1 (`app/` module), mygo `ui` (fork commit `25387f1`: `Modal`, `RadioGroup`, `Radio`, `Field`, `Scroll`, `MustParseSVG`), the existing `hubapi`, `model`, `view`, `hubtest` packages, `sshgate hub` (UI door protocol 12) and `sshtestd` (its `direct-tcpip` and loopback `tcpip-forward`).

## Decisions taken in this plan (controller rulings, on the spec)

1. **Activity rule: no follow-up** (ruling 1). Tunnels need none: Electron applies `tunnels.state` to its list and calls nothing (`App.tsx:152-156`), and so does the app (`App.tunnelState`). `tunnels.list` is read where Electron reads it: beside `servers` when the ready or create-vault screen is entered (`App.tsx:146-149`; the ready screen follows the person's unlock, and the create-vault screen has no vault to keep unlocked), and after the person's own `tunnels.save`, `tunnels.delete`, `servers.save` and `servers.delete` succeed (`App.tsx:215,220`, `TunnelsView.tsx` `onChanged`), only while the ready screen shows. These complete a user action, as `servers` after a save already does, so the spec's activity rule holds as written and is not amended. Slice 1's `TestNotificationsCallOnlyStatus` gains a `tunnels.state`. Cost if wrong: none on the wire.
2. **One Tunnels tab per host** (ruling 4). `TabSet.OpenTunnels` activates the host's Tunnels tab if there is one and adds it otherwise (Electron's `findKind`; Files tabs stay one per click). `MostRecentFor` (Send to tab) and `OpenCount` (the editor's open-tabs count) already count terminals only (`Kind == ""`), so a Tunnels tab is neither a Send to tab target nor in the editor's warning; the warning is otherwise unchanged, as Electron's `HostEditor` names no tunnels (a save that changes the server ends them, and the row shows `server changed`). `endTabs` skips every non-terminal tab; `endTunnelTabs` drops a Tunnels tab's dialog and error on a hub stop. Closing the tab forgets only the tab: its tunnels are the hub's and keep running. The tab gets no focus target (`focusActive` is unchanged). Cost: none.
3. **Lock** (ruling 4). Tunnels survive a lock (the hub owns them), and the hub sends `tunnels.state` behind it (its sink has no lock check, unlike `audit.appended`), so the app keeps applying states while locked and keeps the list across the lock, as Electron clears it only on a hub stop (`App.tsx:150`). The unlock enters the ready screen, which reads `tunnels.list` again. The tab and an open dialog survive the lock, as slice 4's name dialog. Electron's `locked` prop, which disabled Add, Start, Edit and Delete, is not ported: the ready screen, the only place the tab draws, never shows while locked. Cost: none.
4. **The replay buffers.** `reloadTunnels` opens a buffer per call (`App.tunnelBufs`, by call number) before it sends; `tunnelState` appends to every open buffer; the reply applies its buffer (`model.ReplayTunnelStates`) and closes it. A reply after a hub stop is dropped; a failed one keeps the list, as Electron's `catch`. Cost: none.
5. **Stop is a notification.** `tunnels.stop` goes through `Door.Notify` (`App.tunnelsStop`), as `files.cancel` does; it has no reply, so the row changes when `tunnels.state` says `stopped`. `Door`'s comment and the Global Constraints say so. `hubapi.Caller` stays `Call`-only. Cost: none.
6. **Rows, not `ui.Table`.** A Tunnels tab has no selection and no sort, and its rows hold buttons, so it is a `Scroll` of `Row`s with a heading row. Each row's buttons show the bare verb and are named after the row (`Start <label>`, else `Start <forward>`), as slice 4's `Cancel <row>`, because the Tester clicks the first element of a name. The `Label` heading is named `Label column`: a probe showed `Click("Label")` taking the heading behind the open dialog, which dismissed the dialog, while the dialog's field kept its name. Delete has no confirm, as in Electron. Edit and Delete are disabled while a tunnel runs or starts, with the tooltip `Stop it first`. Cost: one heading's accessible name differs from its text.
7. **The dialog.** A `ui.Modal` keyed per open: a `RadioGroup` row named `Kind` (Electron's hints as tooltips), `Listen port` (`AutoFocus`), `Target host` and `Target port` (hidden for Dynamic), `Label`, an error line, Cancel and Save (`PrimaryButton`). Enter in any field saves, as Electron's form; Esc and Cancel close it, except while a save is in flight. The fields are checked by `model.ParseTunnelForm` (Electron's `parseTunnelForm`); the hub checks again and its refusals (`another tunnel already listens on …`, `stop the tunnel first`, `a server holds at most 32 tunnels`) stay in the dialog. One difference: Go's `strings.TrimSpace` does not trim U+FEFF, which JavaScript's `trim` does, so a label or target host with a leading BOM is refused (the hub refuses it too). Save is not a guarded button: it consents to nothing. Cost: a Save, Start or Delete whose reply lands after its tab was closed updates nothing, not even the list (Electron's `onChanged` still reloaded after unmount); the next `tunnels.list` (an unlock, a host write, another save) catches up.
8. **The card.** The Tunnels button is an icon (Electron's `TunnelIcon`, two arrows, as an inline SVG), named `Tunnels <name>`, tooltip `Tunnels`: a word would not fit the 240 px card's action row beside `Files`, `Edit` and `Delete` on Linux and Windows fonts. The badge `N ⇄` (accent, tooltip `Running tunnels`) shows while the host has running tunnels (`model.RunningTunnels`). Cost: the icon and the glyph are checked by hand.
9. **The Auto-allow dialog's remote tunnels** (slice 3b plan Decision 2). `model.RemoteTunnels` gives the host's running remote tunnels' forwards (`App.tsx:314`); the dialog shows them under `Remote tunnels running on this host reach your machine:` in a danger-tinted box, each in monospace, after the root-check lines (Electron's order). `model.DialogChangeKey` gains the list as its last term (`nil` and empty are the same key), so a tunnel starting or stopping while the dialog is open restarts Enable's delay. Ports `AutoAllowDialog.test.ts:104-109` and the tunnels half of `:153-158`. Cost: none.
10. **live-tunnels** (ruling 2). `TestLiveTunnels` (`//go:build unix`) skips unless `SSHGATE_LIVE_HOST` is set, and reuses slice 4's `liveFlow` and `ttyPassword`: a copy of the vault (`SSHGATE_STORE`, else `~/.config/sshgate/servers.json`), the real one never written; the master password read from `/dev/tty` with echo off and typed into the unlock screen twice (at the start and after the lock; Electron asked the person twice); your `HOME` and ssh-agent (a host may log in with the agent) but its own `SSHGATE_RUNTIME_DIR`, so a running sshgate app is untouched. `SSHGATE_LIVE_TUNNEL_TARGET` (default `127.0.0.1:22`) is the target as seen from the server; the SOCKS5 check connects by name, resolved on the server. Both tunnels listen on `127.0.0.1`; the only writes are two `tunnels.save` into the copy. A t.Cleanup sends `tunnels.stop` for any tunnel it started that still runs and waits for `stopped` before its hub ends. A host on auto-allow: the test never opens the host editor (the spec has no editor step), so the Auto-allow dialog cannot ask; a paused or live grant only adds the paused banner above the cards, so the tester is 1000x1200. Its body, `f.liveTunnels`, also runs on sshtestd as `TestFlowLiveTunnels` (sshtestd's own port answers `SSH-`), so a change that would break the opt-in test fails the Gate. No agent runs `TestLiveTunnels`. Cost: about 5 s of Gate time.
11. **Flow coverage.** `TestFlowTunnels` ports `tunnels.spec.ts` (local and dynamic tunnels to an echo listener, a connection counted, the badge `2 ⇄`, both carrying traffic behind the lock on old and new connections, Stop closing the ports, the badge gone) and checks the hub's `kind: "tunnel"` audit records (start with the listen address, end with `stopped` and the connection total). `TestFlowTunnelsRemoteWarnsAndEndsOnServerChange` runs a remote forward through sshtestd's loopback `tcpip-forward`, sees it listed in the Auto-allow dialog, then changes the host's port in the editor and sees the row read `server changed` (audited with that reason). Not covered by a flow: a connection lost under a running tunnel (the hub's `TestTunnelEndedByServerChangeAndConnectionLoss` owns it; the row shows `connection lost` as any hub error) and a port already in use (on Windows the hub passes the OS's text; a view test shows a hub error in the row and the error line).
12. **No hub change** (ruling). Every call and text this slice needs is in protocol 12. Hub facts the app relies on, each checked by Task 1's `TestTunnelsAgainstRealHub` or a flow: `tunnels.save` answers the saved tunnel with the id it gave a new one; `tunnels.state` goes out for every change (`starting`, `running`, `stopped`), behind the lock too; a running tunnel keeps forwarding across a lock; `tunnels.list` answers while locked (it also counts as UI activity: `h.touch()` in `registerTunnelMethods`, read in the source, not tested here); `tunnels.stop` is a notification that works while locked; `tunnels.start` and `tunnels.save` answer `Vault is locked; unlock it in the app` while locked; a running tunnel cannot be edited (`stop the tunnel first`); a save that changes the server ends its tunnels with `server changed`.
13. **Safety** (ruling 3). Tests start hubs only through `hubtest` (temp `HOME`, `SSH_AUTH_SOCK=`, their own store and short `SSHGATE_RUNTIME_DIR`); every listener and tunnel in a test binds `127.0.0.1`; no test starts the GUI or touches `~/.ssh`, `~/.config/sshgate`, `~/Library/Application Support/sshgate-app`, `/Applications`, or the mygo checkout; Go source holds no raw invisible or bidi rune (the Gate's byte check). `TestLiveTunnels` is the one opt-in exception (Decision 10). Cost: none.

// echo serves 127.0.0.1:0, writing back what each connection sends, until
// the test ends.
func echo(t *testing.T) int {
	t.Helper()
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		t.Fatal(err)
	}
	t.Cleanup(func() { l.Close() })
	go func() {
		for {
			c, err := l.Accept()
			if err != nil {
				return
			}
			go func() { io.Copy(c, c); c.Close() }()
		}
	}()
	return l.Addr().(*net.TCPAddr).Port
}

// freePort is a loopback port nothing listens on right now.
func freePort(t *testing.T) int {
	t.Helper()
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		t.Fatal(err)
	}
	defer l.Close()
	return l.Addr().(*net.TCPAddr).Port
}

// ping sends "ping" through 127.0.0.1:port and wants it back.
func ping(t *testing.T, port int) {
	t.Helper()
	c, err := net.DialTimeout("tcp", net.JoinHostPort("127.0.0.1", strconv.Itoa(port)), 5*time.Second)
	if err != nil {
		t.Fatal(err)
	}
	defer c.Close()
	c.SetDeadline(time.Now().Add(5 * time.Second))
	if _, err := c.Write([]byte("ping")); err != nil {
		t.Fatal(err)
	}
	b := make([]byte, 4)
	if _, err := io.ReadFull(c, b); err != nil || string(b) != "ping" {
		t.Fatalf("got %q %v", b, err)
	}
}

// TunnelSummary is a tunnel's forward in one line: "L 127.0.0.1:5433 →
// db:5432", "R server 127.0.0.1:8080 → localhost:3000" or "D
// 127.0.0.1:1080 SOCKS5". An IPv6 target is bracketed.
func TunnelSummary(t hubapi.Tunnel) string {
	listen := "127.0.0.1:" + strconv.Itoa(t.ListenPort)
	to := net.JoinHostPort(t.TargetHost, strconv.Itoa(t.TargetPort))
	switch t.Kind {
	case "local":
		return "L " + listen + " → " + to
	case "remote":
		return "R server " + listen + " → " + to
	default:
		return "D " + listen + " SOCKS5"
	}
}

// tunnelPort is s as a port, or 0 when it is not 1-65535.
func tunnelPort(s string) int {
	s = strings.TrimSpace(s)
	if len(s) < 1 || len(s) > 5 || strings.ContainsFunc(s, func(r rune) bool { return r < '0' || r > '9' }) {
		return 0
	}
	n, _ := strconv.Atoi(s)
	if n > 65535 {
		return 0
	}
	return n
}

func controlOrFormat(r rune) bool { return unicode.Is(unicode.Cc, r) || unicode.Is(unicode.Cf, r) }

// ParseTunnelForm checks the dialog's fields as config.Tunnel.Validate does
// (the hub checks again) and gives the tunnel to save under id, or the
// first error to show.
func ParseTunnelForm(f TunnelForm, id string) (hubapi.Tunnel, string) {
	listen := tunnelPort(f.ListenPort)
	if listen == 0 {
		return hubapi.Tunnel{}, "Listen port must be 1-65535"
	}
	label := strings.TrimSpace(f.Label)
	if len(label) > 64 || strings.ContainsFunc(label, controlOrFormat) {
		return hubapi.Tunnel{}, "Label is at most 64 bytes, with no control characters"
	}
	if f.Kind == "dynamic" {
		return hubapi.Tunnel{ID: id, Kind: "dynamic", ListenPort: listen, Label: label}, ""
	}
	host := strings.TrimSpace(f.TargetHost)
	if host == "" || len(host) > 253 || strings.ContainsFunc(host, func(r rune) bool { return unicode.IsSpace(r) || controlOrFormat(r) }) {
		return hubapi.Tunnel{}, "Target host is required, with no spaces or control characters"
	}
	target := tunnelPort(f.TargetPort)
	if target == 0 {
		return hubapi.Tunnel{}, "Target port must be 1-65535"
	}
	return hubapi.Tunnel{ID: id, Kind: f.Kind, ListenPort: listen, TargetHost: host, TargetPort: target, Label: label}, ""
}

// FormFor fills the dialog: t's fields, or a new local tunnel to localhost.
func FormFor(t *hubapi.Tunnel) TunnelForm {
	if t == nil {
		return TunnelForm{Kind: "local", TargetHost: "localhost"}
	}
	f := TunnelForm{Kind: t.Kind, ListenPort: strconv.Itoa(t.ListenPort), TargetHost: t.TargetHost, Label: t.Label}
	if t.TargetPort != 0 {
		f.TargetPort = strconv.Itoa(t.TargetPort)
	}
	return f
}

// TunnelLive is a tunnel that runs or is starting: it can be stopped, not
// edited or deleted.
func TunnelLive(status string) bool { return status == "running" || status == "starting" }

// ApplyTunnelState sets the matching row's status, error and conns (an
// error from before goes); a state for a tunnel not listed changes nothing.
func ApplyTunnelState(list []hubapi.TunnelView, s hubapi.TunnelState) []hubapi.TunnelView {
	i := slices.IndexFunc(list, func(t hubapi.TunnelView) bool { return t.Server == s.Server && t.ID == s.ID })
	if i < 0 {
		return list
	}
	next := slices.Clone(list)
	next[i].Status, next[i].Error, next[i].Conns = s.Status, s.Error, s.Conns
	return next
}

// ReplayTunnelStates applies the states that arrived while a tunnels.list
// was in flight to its reply, in order, so an older snapshot never
// overwrites a newer status.
func ReplayTunnelStates(list []hubapi.TunnelView, events []hubapi.TunnelState) []hubapi.TunnelView {
	for _, e := range events {
		list = ApplyTunnelState(list, e)
	}
	return list
}

// RunningTunnels counts server's running tunnels: the host card's badge.
func RunningTunnels(list []hubapi.TunnelView, server string) int {
	n := 0
	for _, t := range list {
		if t.Server == server && t.Status == "running" {
			n++
		}
	}
	return n
}

// RemoteTunnels are the summaries of server's running remote tunnels, which
// the Auto-allow dialog warns about: they reach this machine from the
// server.
func RemoteTunnels(list []hubapi.TunnelView, server string) []string {
	var out []string
	for _, t := range list {
		if t.Server == server && t.Kind == "remote" && t.Status == "running" {
			out = append(out, TunnelSummary(t.Tunnel))
		}
	}
	return out
}

// openTunnels shows server's Tunnels tab, adding it the first time.
func (a *App) openTunnels(server string) string {
	id := a.tabs.OpenTunnels(server)
	if a.tunnelTabs[id] == nil {
		a.tunnelTabs[id] = &tunnelsTab{server: server}
	}
	return id
}

// reloadTunnels reads tunnels.list. The tunnels.state notes that arrive
// while it is in flight are kept and applied to its reply (Electron's
// tunnelBuffers), so an older snapshot never hides a newer status. A
// failed read keeps the list shown.
func (a *App) reloadTunnels() {
	a.tunnelSeq++
	n, gen := a.tunnelSeq, a.hubGen
	a.tunnelBufs[n] = []hubapi.TunnelState{}
	go func() {
		l, err := a.hub().TunnelsList(context.Background())
		a.Update(func() {
			buf := a.tunnelBufs[n]
			delete(a.tunnelBufs, n)
			if gen != a.hubGen || err != nil {
				return
			}
			a.tunnels = model.ReplayTunnelStates(l, buf)
		})
	}()
}

// tunnelState applies a tunnels.state note; it calls nothing. The hub sends
// them behind the lock too, so the list stays true across a lock.
func (a *App) tunnelState(e hubapi.TunnelState) {
	a.tunnels = model.ApplyTunnelState(a.tunnels, e)
	for n, buf := range a.tunnelBufs {
		a.tunnelBufs[n] = append(buf, e)
	}
}

// tunnelsStop is a notification: it works behind the lock and answers nothing.
func (a *App) tunnelsStop(server, id string) {
	a.Door.Notify("tunnels.stop", map[string]string{"server": server, "id": id})
}

// tunnelAct runs a row's Start or Delete. Its error shows in the tab; a
// delete then reads the list again, while the ready screen shows.
func (a *App) tunnelAct(id, tid string, del bool) {
	v := a.tunnelTabs[id]
	v.err = ""
	gen, server := a.hubGen, v.server
	go func() {
		var err error
		if del {
			err = a.hub().TunnelsDelete(context.Background(), server, tid)
		} else {
			err = a.hub().TunnelsStart(context.Background(), server, tid)
		}
		a.Update(func() {
			if gen != a.hubGen || a.tunnelTabs[id] != v {
				return
			}
			if err != nil {
				v.err = err.Error()
				return
			}
			if del && a.ready(gen) {
				a.reloadTunnels()
			}
		})
	}()
}

// saveTunnel checks the dialog's fields, then sends tunnels.save. On success
// the dialog closes and, while the ready screen shows, the list is read
// again; on error it stays open with the message.
func (a *App) saveTunnel(id string) {
	v := a.tunnelTabs[id]
	dl := v.dlg
	if dl.busy {
		return
	}
	tid := ""
	if dl.edit != nil {
		tid = dl.edit.ID
	}
	t, e := model.ParseTunnelForm(dl.form, tid)
	if e != "" {
		dl.err = e
		return
	}
	dl.busy, dl.err = true, ""
	gen, server := a.hubGen, v.server
	go func() {
		_, err := a.hub().TunnelsSave(context.Background(), server, t)
		a.Update(func() {
			if gen != a.hubGen || a.tunnelTabs[id] != v || v.dlg != dl {
				return
			}
			dl.busy = false
			if err != nil {
				dl.err = err.Error()
				return
			}
			v.dlg = nil
			if a.ready(gen) {
				a.reloadTunnels()
			}
		})
	}()
}

		ui.Row(c).Gap(6).Width(170).Children(func() {
			if live {
				if ui.Button(c, "Stop").Label("Stop " + name).Clicked() {
					act = func() { a.tunnelsStop(server, id) }
				}
			} else if ui.Button(c, "Start").Label("Start " + name).Clicked() {
				act = func() { a.tunnelAct(tab, id, false) }
			}

}

// echoServer serves 127.0.0.1:0, writing back what each connection sends,
// until the test ends.
func echoServer(t *testing.T) int {
	t.Helper()
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		t.Fatal(err)
	}
	t.Cleanup(func() { l.Close() })
	go func() {
		for {
			c, err := l.Accept()
			if err != nil {
				return
			}
			go func() { io.Copy(c, c); c.Close() }()
		}
	}()
	return l.Addr().(*net.TCPAddr).Port
}

// freePort is a loopback port nothing listens on right now.
func freePort(t *testing.T) int {
	t.Helper()
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		t.Fatal(err)
	}
	defer l.Close()
	return l.Addr().(*net.TCPAddr).Port
}

func loopback(port int) string { return net.JoinHostPort("127.0.0.1", strconv.Itoa(port)) }

// connect opens a connection to 127.0.0.1:port, closed when the test ends.
func connect(t *testing.T, port int) net.Conn {
	t.Helper()
	c, err := net.DialTimeout("tcp", loopback(port), 5*time.Second)
	if err != nil {
		t.Fatal(err)
	}
	t.Cleanup(func() { c.Close() })
	return c
}

// readN reads n bytes from c, failing after 15 s.
func readN(t *testing.T, c net.Conn, n int) []byte {
	t.Helper()
	c.SetReadDeadline(time.Now().Add(15 * time.Second))
	b := make([]byte, n)
	if _, err := io.ReadFull(c, b); err != nil {
		t.Fatalf("read %d bytes: %v", n, err)
	}
	return b
}

// pingOn sends "ping" on c and wants it back (the e2e's ping).
func pingOn(t *testing.T, c net.Conn) {
	t.Helper()
	if _, err := c.Write([]byte("ping")); err != nil {
		t.Fatal(err)
	}
	if b := readN(t, c, 4); string(b) != "ping" {
		t.Fatalf("got %q", b)
	}
}

// socks opens a SOCKS5 CONNECT to 127.0.0.1:target through the proxy on port.
func socks(t *testing.T, port, target int) net.Conn {
	t.Helper()
	c := connect(t, port)
	c.Write([]byte{5, 1, 0})
	if b := readN(t, c, 2); b[0] != 5 || b[1] != 0 {
		t.Fatalf("greeting %v", b)
	}
	c.Write([]byte{5, 1, 0, 1, 127, 0, 0, 1, byte(target >> 8), byte(target)})
	if b := readN(t, c, 10); b[1] != 0 {
		t.Fatalf("connect reply %v", b)
	}
	return c
}
