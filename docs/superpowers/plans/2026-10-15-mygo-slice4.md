# mygo desktop, slice 4 (Files) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The native mygo app browses and moves files over SFTP the way the Electron app does:
- a **Files tab** for each click on a host card's `Files` button (several per host, as Electron), with Up, Path, Refresh, Show hidden files, a sortable file table (folders first), the truncated and unsafe-name notes, and Enter, Backspace, F2 and Delete on the table;
- **New folder** and **Rename** dialogs that act on the folder they opened in, and list it again only if it is still shown;
- **jobs**: Upload files, Upload folder and a drop from the Finder, Download into a picked folder, Delete; `files.planned` runs a job with nothing to overwrite at once and asks otherwise; the **conflict** and **delete** dialogs (mouse-only Overwrite all, Skip existing and Delete behind the 500 ms guard, the typed word for a recursive delete, Cancel by Enter and Esc); the **Transfers** list with progress, Cancel, Dismiss and the hub's errors;
- the host-key prompt retrying `files.list`; the host editor's `cancel N transfers` warning; jobs across a lock, a hub restart, a closed tab and a server change;
- the e2e spec `files` ported as Go flow tests against a real `sshgate hub` and `sshtestd -sftp-root`, and `live-files` as an opt-in test against a real host;
- the spec's activity rule, download-conflict and quit texts amended to the real wire (Task 1).

**Architecture:**
- **Layers.** Unchanged: `hubapi` (typed door calls and notifications), `model` (pure rules, their vitest cases as Go table tests), `view` (the `App` controller and its screens), `internal/hubtest` (sshgate, sshtestd, now with an SFTP root).
- **State.** A Files tab is a `model.Tab` of kind `files` plus a `filesTab` on `App`, by tab id. Its jobs are `fileJob`s, held in start order on the tab (the Transfers list) and, while live, in `App.jobs` by job id, so a `files.*` notification finds its job or nothing.
- **Dialogs.** New folder, Rename, the conflict and the delete dialog are `ui.Modal`s. The job dialogs reuse the slice-1 guard (`guard`, `MouseButton`, `model.ListChanges` keyed by job id); the shown dialog is derived each frame from the oldest job waiting on its tab, as Electron's `confirmJob`.
- **Native pickers** are two new `view.Shell` methods, called off the main thread; their answer comes back through `Update`. A drop is handed to `App.dropFiles`, which checks the paths.

**Tech Stack:** Go 1.27.1 (`app/` module), mygo `ui` (fork commit `25387f1`: `Table`, `ListState`, `Selection`, `Progress`, `Modal`, `DroppedFiles`, `Dialog.Open`), the existing `hubapi`, `model`, `view`, `hubtest` packages, `sshgate hub` (UI door protocol 12) and `sshtestd -sftp-root`.

**Spec:** `docs/superpowers/specs/2026-10-14-mygo-desktop-design.md` (Slices row 4; Architecture → "Door client" → Activity rule; "Files"; "Crash"; "Testing"). ## Review Focus

1. **Calls after a notification.** `files.run` and `files.list` go out only for a job this app planned and still holds, at most once each, and only while the ready screen shows; behind the lock only `files.cancel`, a notification. Covered by Task 4 (`TestNotificationsCallOnlyStatus`, extended; `TestUploadRunsThenRelistsOnce`; `TestLockCancelsWhatWaitsForTheDialog`; `TestHubStopAndCloseEndJobs`).
2. **A job waiting for its dialog when the ground moves**: a lock, a hub restart, a closed tab, a server change, a plan expiring. The dialog goes, the hub's job is cancelled or already ended, and nothing runs later. Covered by Task 4 (`TestLockCancelsWhatWaitsForTheDialog`, `TestHubStopAndCloseEndJobs`) and Task 5 (`TestFlowFilesLockAndServerChange`, which also checks the hub no longer holds the job).
3. **Content that moves under the pointer right before a click** on Overwrite all, Skip existing or Delete: a second job's dialog replacing the first. Each is mouse-only and waits 500 ms per job; Enter cancels. Covered by Task 4 (`TestUploadConflictAsksAndWaits`, `TestDeleteNeedsTheWordAndTheDelay`).
4. **Local paths from outside the app.** A drop's paths are checked (count, absolute, present) before `files.plan`; picker paths come from the OS's own dialog; the hub checks both again (`IsAbs`, `os.Root`). Covered by Task 4 (`TestDropChecksThePaths`).
5. **The folder an action targets** is the one shown when its dialog or picker opened, not one navigated to since. Covered by Task 3 (`TestNewFolderGoesWhereItOpened`) and Task 5 (`TestFlowFilesNewFolderStays`).
6. **A remote name with a bidi or invisible rune** in a conflict sample or a picker title. It shows only escaped. Covered by Task 2 (`TestFilesTexts`) and Task 4 (`TestDownloadSkipsOrAsks`).

## Decisions taken in this plan (controller rulings, on the spec)

1. **Activity rule: bounded follow-ups** (ruling 1). Electron carries a job on from its own notifications (`FilesView.tsx` `onJobEvent`, `finishJob`), and `files.spec.ts` depends on it: a plain upload runs without a second click, and the folder lists again after an upload or delete. The app does the same, bounded: on `files.planned` it may send `files.run` (an upload or download with no conflicts: `skip`; with conflicts, the person's choice in the app's dialog) or re-send `files.cancel` for a Cancel pressed while planning; on `files.done` of an upload or delete it may send one `files.list` of the folder shown (`relistAfterJob`); only for a job id this app planned and still holds, and only while unlocked on the same hub (`a.ready(gen)`). A job whose `files.planned` lands behind the lock is cancelled with `files.cancel` (it cannot run: the hub refuses `files.run` while locked) and its row reads `Cancelled: vault locked`. A job that ends behind the lock does not relist: the listing stays as it was until Refresh (Electron relisted, got `Vault is locked`, and blanked the listing). `files.run` and `files.list` count as UI activity, so a long job that ends restarts the idle timer once, as in Electron. Task 1 amends the spec's activity rule; Task 4 extends slice 1's `TestNotificationsCallOnlyStatus` (files notes for an unknown id call and send nothing) and adds tests that bound the follow-ups of planned ids. One window stays: a `files.planned` that lands after the hub's `locked` notification but before the `status` reply moves the screen still sends its one `files.run`; the hub refuses it (`Vault is locked; unlock it in the app`), the app sends `files.cancel`, and the row shows that error, as Electron's would. Cost if wrong: one extra idle period after a long transfer.
2. **Quit** (ruling 2). The app has no quit code that sends `term.closeAll`: `main` stops the supervisor, whose `Proc.Stop` closes the hub's stdin; the hub's door then cancels every job with the reason `app closed`, waits up to 5 s, and exits. `files.cancelAll` would audit `renderer reloaded`, untrue here, and nothing in the app resets a renderer (a panic ends the app and the hub). Neither is sent; Task 1 amends the spec's Door client "Methods" line and Crash → Quit. Cost: none.
3. **Download conflicts in the app's dialog** (spec "Files"). The hub takes only `overwrite` or `skip` (`internal/hub/filejobs.go:337-338`); Electron's `ask` lived between its renderer and main, which showed a native box. Here a download with conflicts waits in the same in-window conflict dialog as an upload (`model.PlannedAction` says `confirm` where Electron said `ask`), so its row reads `Waiting for you` (Electron showed an empty progress bar while its box was up). The dialog names the destination: `in <local folder>` for a download, `in <server>:<folder>` for an upload (the spec's bullet; Electron's upload dialog named none). "The same job" (`files.ts:148-151`) holds by construction: the dialog is drawn each frame from a job still in `confirm`, its buttons act on that job, and a job the hub ended meanwhile (`plan expired`, `server changed`) has left `confirm`, so its dialog is gone. Task 1 rewords the spec's bullets. Cost if wrong: none on the wire; the look differs from Electron's native box.
4. **Upload: two buttons, pickers on `Shell`** (ruling 3). mygo's `Dialog.Open` picks files or folders, never both (`dialog.go:131-132`), so every platform gets `Upload files` and `Upload folder` (Electron's macOS had one `Upload`). The pickers are `Shell.PickPaths(title, dirs) ([]string, error)` and `Shell.PickFolder(title) (string, error)`: `trayShell` calls `mygo.Dialog.Open` as a sheet on the window, `noShell` answers an error, `fakeShell` canned paths. They block, so the app calls them in a goroutine; the answer is dropped unless `a.ready(gen)` and the tab is still the same, and a picker error shows in the tab's error note. An upload goes into the folder the picker's title named, captured when it opened (Electron read the folder again after its picker closed). Cost: one more button on macOS.
5. **Drop** (ruling 4). `App.dropFiles(id, paths)` holds the logic, unit-tested directly: nothing unless the tab can act (`ActionsReady`, ready screen); at most `model.MaxDrop` (1000) paths; each absolute and present (`os.Lstat`); then an upload into the folder shown. The wiring in `buildFiles` (`zone.DroppedFiles()`, and an accent border while `FileDragOver`) is one line each, which the Tester cannot drive (no file-drop API): it is on the hand-check list. Cost: none beyond the hand check.
6. **Lock, hub stop and a closed tab** (ruling 5). When the ready screen goes (`setScreen`, lock or hub stop), `dropConfirms` cancels every job waiting for a conflict or delete dialog, the shown one and the queued ones (`files.cancel`, row `Cancelled: vault locked`), so no dialog comes back after an unlock and the hub frees the job at once. Jobs planning or running keep going across the lock, as the hub allows; one planned behind the lock is cancelled (Decision 1). A hub stop (`endFiles`) ends every live job with `hub restarted`, drops a load in flight (the note `hub restarted` when the tab has no listing) and the name dialog. Closing a Files tab sends `files.cancel` for each live job and forgets them. The name dialog survives a lock, as in Electron: it holds no secret, and its request after the unlock is a user action. Cost: a confirm left open at an idle lock must be started again.
7. **Tabs** (ruling 6). `model.Tab` gains `Kind` (`""` a terminal, `model.FilesKind`); `TabSet.OpenFiles` adds a new Files tab on every call (Electron has no dedup), open at once, never exiting. `MostRecentFor` (Send to tab) and `OpenCount` (the editor's open-tabs count) count terminals only, as Electron's `kind === 'term'`; `App.transfers(server)`, the server's live jobs, fills the editor warning's transfers slot (`editor.go`, was `0`), so a port change warns `Saving will cancel 1 transfer.`. The strip shows a Files tab as `<name> · files` (Electron: a folder icon before the name); `endTabs` skips Files tabs; `focusActive` focuses the file table. Host keys: a `hostKeyUnknown` listing joins the shared prompt queue under the tab id; Trust retries `files.list` with `trustHostKey` and reloads the host list (the card's New key goes), Cancel shows `host key not trusted`; `hostKeyMismatch` opens the mismatch dialog and shows `host key mismatch`. A newer load drops a prompt still waiting. Cost: none.
8. **Remembered folder and Show hidden files** (ruling 7). Electron kept both in `localStorage`; no e2e assertion checks them across a restart (live-files clears the folder before it runs). The app keeps them in memory for the run: `App.lastFolder` by server (a new Files tab lists it, and home when it fails) and one `App.showHidden` for every tab. Never in `theme.json`, which `saveTheme` rewrites whole. Cost: after a restart a tab opens at home and hidden names are hidden.
9. **Electron quirks fixed** (ruling 8). None of these is what a ported e2e assertion checks (`Cancelled`, `Uploaded 2`, `skipped 2`, `Downloaded 0 · skipped 2`, `Cancelled: server changed`):
   - a job the person cancelled reads `Cancelled · uploaded N`, not `Cancelled: cancelled · …`;
   - real plurals: `1 file, 1 folder, 0 links`, `1 error`;
   - a `files.done` that is not cancelled but carries a reason (a refused plan, a lost connection) reads `Failed: <reason> · uploaded 0`, not a bare `Uploaded 0`;
   - Esc cancels the conflict and delete dialogs (the modal's `Dismissed`), as the app's other dialogs;
   - a download waiting for its conflict choice reads `Waiting for you` (Decision 3).
10. **The file table is `ui.Table`.** mygo's `Table` with `ListState` (selection by name, `SortOrder`) replaces Electron's hand-built grid, so `windowRange` and `nextSelection` are not ported (the table virtualizes, and selects by click, Shift-click and Cmd-click, as Electron did, plus Up, Down and Home, which Electron's grid lacked). Enter on a row (`Activated`) opens a folder or a link, as a double-click does; Backspace goes up; F2 renames one row; the Delete key deletes. Sorting is the app's (`model.SortEntries`: folders first). Rename is a dialog, not inline: an `EditableText` in a table takes Enter from `Activated` (probed). The delete dialog's button shows `Delete` but is named `Delete for good` (`mouseButtonNamed`), because the Tester clicks the first element named `Delete`, the toolbar's; the label keeps the visible word first. Three inline SVGs mark folders, files and links. Not ported: `aria-busy` (tests read `loading`), the restored scroll offset, and `.dropping`'s dashed outline (an accent border instead).
11. **live-files** (ruling 9). `TestLiveFiles` (`//go:build unix`) skips unless `SSHGATE_LIVE_HOST` is set. It copies the vault (`SSHGATE_STORE`, else `~/.config/sshgate/servers.json`) to a temp dir and never writes the real one; reads the master password from `/dev/tty` with echo off (`stty -echo`: `golang.org/x/term` is not in `app/go.mod`, and one opt-in test does not add it) and types it into the unlock screen; runs the hub with your `HOME` and ssh-agent (a host may log in with the agent; Electron's `launchLive` kept the whole environment) but its own `SSHGATE_RUNTIME_DIR`, so a running sshgate app is untouched; writes remotely only inside `<home>/sshgate-e2e-<ms>` (`deleteByName` refuses any other name), cleaning up after itself, on a fresh vault copy when the port was changed. Rows are chosen through the selection (`f.choose`), since the table only shows rows in view, as the e2e scrolled its grid. The spec's tests become logged sections of one test (a subtest cannot use the outer flow's `Fatal`). The Finder drop is a hand check. No agent runs it; the plan only compiles it.
12. **Flow coverage** (ruling 11). `TestFlowFiles` and `TestFlowFilesNewFolderStays` port `files.spec.ts`'s two tests; the second navigates under the open dialog through the model (mygo's modal takes the pointer; Electron filled the Path box behind it). `TestFlowFilesLockAndServerChange` locks through the setup door (the Lock button sits behind the delete dialog; an idle lock does the same) and checks that the hub no longer holds the job; for the server change it shows the Hosts tab through the model (the modal takes the pointer), then edits the port through the editor and checks the warning, the save, and the row's `Cancelled: server changed · deleted 0`. sshtestd has no SFTP fault or stall flags, so these are not covered by a flow: a transfer running across a lock (the hub's `TestJobCancelWhileRunningAndWhileLocked`, and live-files), a running transfer ended by a server change (live-files), `permission denied` (live-files), a real progress bar (view test with fake notes).
13. **No hub change** (ruling 10). Every call and text this slice needs is in protocol 12. Hub facts the app relies on, each checked by Task 1's `TestFilesAgainstRealHub` or a flow: `files.run` takes only `overwrite` or `skip`; `files.cancel` is a notification that works while locked and ignores an unknown id; `files.done` comes once per job the hub took, after `files.planned` when there is one; a job id is free again after its `files.done`; `files.list` answers a host-key result (not an error) and pins on a retry with `trustHostKey`; `files.*` notifications are sent while locked; a closed door cancels its jobs (`app closed`).
14. **Job ids and `files.cancel`.** Job ids are `f1`, `f2`, … from `App.jobSeq`, never reused while the app runs (a hub restart does not reset it), so a live id is never planned twice and the spec's "a plan whose id is still live is refused" holds by construction. `App.jobs` holds only live jobs, so a note for an ended or unknown id finds nothing, and `files.run` is sent only for a planned job. `files.cancel` goes straight from the view through `Door.Notify` (`view.Door` gains it; `main`'s `liveDoor` and the tests' `fakeDoor` implement it); `hubapi.Caller` stays `Call`-only. Only the protocol's keys are sent (`hubapi.FilesPlan`'s struct; `dest` omitted for a delete).

package model

import (
	"cmp"
	"fmt"
	"slices"
	"strings"
	"time"

)

// DeleteWord is what a recursive delete asks the person to type.
const DeleteWord = "delete"

// MaxDrop is how many paths one drop may hold (Electron's MAX_DROP; the hub
// takes 1 to 1000 sources).
const MaxDrop = 1000

// SortEntries returns es sorted for the file list (desktop/src/renderer/
// files.ts): folders first, then the rest, each by key ("name", "size",
// "mtime" or "mode"), descending when desc; ties by name, ascending.
func SortEntries(es []hubapi.FileEntry, key string, desc bool) []hubapi.FileEntry {
	out := slices.Clone(es)
	slices.SortStableFunc(out, func(a, b hubapi.FileEntry) int {
		if ad, bd := a.Kind == "dir", b.Kind == "dir"; ad != bd {
			if ad {
				return -1
			}
			return 1
		}
		var c int
		switch key {
		case "size":
			c = cmp.Compare(a.Size, b.Size)
		case "mtime":
			c = cmp.Compare(a.Mtime, b.Mtime)
		case "mode":
			c = cmp.Compare(a.Mode, b.Mode)
		default:
			c = strings.Compare(a.Name, b.Name)
		}
		if desc {
			c = -c
		}
		if c != 0 {
			return c
		}
		return strings.Compare(a.Name, b.Name)
	})
	return out
}

// VisibleEntries drops dot names unless showHidden.
func VisibleEntries(es []hubapi.FileEntry, showHidden bool) []hubapi.FileEntry {
	if showHidden {
		return es
	}
	return slices.DeleteFunc(slices.Clone(es), func(x hubapi.FileEntry) bool { return strings.HasPrefix(x.Name, ".") })
}

func FormatSize(n int64) string {
	if n < 1024 {
		return fmt.Sprintf("%d B", n)
	}
	v := float64(n)
	unit := ""
	for _, u := range []string{"KB", "MB", "GB", "TB", "PB"} {
		v, unit = v/1024, u
		if v < 1024 {
			break
		}
	}
	return fmt.Sprintf("%.1f %s", v, unit)
}

// FormatMode is ls's mode column: d, l or -, then the rwx of the low 9 bits.
func FormatMode(kind string, mode uint32) string {
	b := []byte("-")
	switch kind {
	case "dir":
		b[0] = 'd'
	case "link":
		b[0] = 'l'
	}
	for i := 8; i >= 0; i-- {
		if mode&(1<<i) != 0 {
			b = append(b, "rwx"[(8-i)%3])
		} else {
			b = append(b, '-')
		}
	}
	return string(b)
}

// FormatTime shows Unix seconds as "YYYY-MM-DD HH:MM" in loc.
func FormatTime(sec int64, loc *time.Location) string {
	return time.Unix(sec, 0).In(loc).Format("2006-01-02 15:04")
}

func JoinPath(dir, name string) string {
	if strings.HasSuffix(dir, "/") {
		return dir + name
	}
	return dir + "/" + name
}

// ParentPath is p's folder; "" and "/" have none.
func ParentPath(p string) (string, bool) {
	if p == "" || p == "/" {
		return "", false
	}
	i := strings.LastIndex(p, "/")
	if i <= 0 {
		return "/", true
	}
	return p[:i], true
}

// NameError is why name cannot be a new folder or rename target, or "".
func NameError(name string) string {
	switch {
	case name == "" || name == "." || name == "..":
		return "Enter a name."
	case strings.ContainsAny(name, "/\\\x00"):
		return `A name cannot contain /, \, or NUL.`
	}
	return ""
}

// folder with contents, or one the walk could not read) needs DeleteWord.
func DeleteNeedsTyping(hasFolder bool, selected int, p hubapi.FilesPlanned) bool {
	return hasFolder && p.Files+p.Dirs+p.Links+p.ErrorCount > selected
}

func PruneSelection(sel []string, entries []hubapi.FileEntry) []string {
	var out []string
	for _, n := range sel {
		if slices.ContainsFunc(entries, func(x hubapi.FileEntry) bool { return x.Name == n }) {
			out = append(out, n)

// DoneSummary is a finished job's line: the hub's counts, or err for a job
// that ended without files.done (a refused plan, a hub restart).
func DoneSummary(d *hubapi.FilesDone, err string) string {
	if d == nil {
		return err
	}
	verb, n := "Uploaded", d.Copied
	switch d.Op {
	case "download":
		verb = "Downloaded"
	case "delete":
		verb, n = "Deleted", d.Deleted
	}
	parts := []string{fmt.Sprintf("%s %d", verb, n)}
	if d.Skipped > 0 {
		parts = append(parts, fmt.Sprintf("skipped %d", d.Skipped))
	}
	if d.ErrorCount > 0 {
		parts = append(parts, fmt.Sprintf("%d error%s", d.ErrorCount, plural(d.ErrorCount)))
	}
	head := ""
	switch {
	case d.Cancelled && (d.Reason == "" || d.Reason == "cancelled"):
		head = "Cancelled"
	case d.Cancelled:
		head = "Cancelled: " + d.Reason
	case d.Reason != "":
		head = "Failed: " + d.Reason
	default:
		return strings.Join(parts, " · ")
	}
	parts[0] = strings.ToLower(parts[0][:1]) + parts[0][1:]
	return head + " · " + strings.Join(parts, " · ")
}

// openFiles adds a Files tab for server, which lists the folder last shown

func (a *App) openFiles(server string) string {
	id := a.tabs.OpenFiles(server)
	a.files[id] = &filesTab{server: server, sel: -1, sort: ui.SortOrder{Column: "Name"}}

// loadFiles lists p ("" is home) in tab id. trust is set on the retry after
// a host-key prompt; homeOnFail lists home when p fails (the remembered
// folder may be gone).
func (a *App) loadFiles(id, p string, trust *hubapi.Trust, homeOnFail bool) {
	v := a.files[id]
	v.loadGen++
	gen, lg, server := a.hubGen, v.loadGen, v.server
	v.requested, v.loading, v.err, v.pathIn = p, true, "", p
	a.prompts.Drop(id) // a newer load supersedes a prompt still waiting
	go func() {
		l, err := a.hub().FilesList(context.Background(), server, p, trust)
		a.Update(func() { a.listed(id, gen, lg, l, err, trust != nil, homeOnFail) })
	}()
}

// listed applies a files.list reply, unless its hub stopped, its tab
// closed, or a later load superseded it. A reply landing behind the lock
// screen still applies: the tab shows it after the unlock.
func (a *App) listed(id string, gen, lg int, l hubapi.FileListing, err error, trusted, homeOnFail bool) {
	v := a.files[id]
	if v == nil || gen != a.hubGen || lg != v.loadGen {
		return
	}
	if err == nil && l.Status == "hostKeyUnknown" {
		a.prompts.Ask(id, l.HostKey) // still loading until the person answers
		return
	}
	if err == nil && l.Status == "hostKeyMismatch" {
		k := l.HostKey
		a.mismatch = &k
		err = errors.New("host key mismatch")
	}
	v.loading = false
	if err != nil {
		if homeOnFail {
			a.loadFiles(id, "", nil, false)
			return
		}
		v.listing, v.err = nil, err.Error()
	} else {
		if v.shown == l.Path { // a relist: the selection stays, less what went
			keep := model.PruneSelection(slices.Collect(v.selection.All()), l.Entries)
			v.selection.Clear()
			for _, n := range keep {
				v.selection.Add(n)
			}
		} else {
			v.selection.Clear()
			v.sel = -1
		}
		v.listing, v.shown, v.requested, v.pathIn = &l, l.Path, l.Path, l.Path
		a.lastFolder[v.server] = l.Path
		a.sortFiles(v)
		if trusted {
			a.reloadServers() // the card's New key goes
		}
	}
	if f := v.relist; f != "" {
		v.relist = ""
		if f == v.shown && f == v.requested && a.ready(gen) {
			a.loadFiles(id, f, nil, false)
		}
	}
}

// startJob plans a job in tab id. Job ids are "f1", "f2", …: the app's own,
// never reused while it runs, so a live id is never planned twice. Only the
// protocol's keys are sent.
func (a *App) startJob(id, op string, sources []string, dest, folder, label string) *fileJob {
	v := a.files[id]
	a.jobSeq++
	j := &fileJob{id: fmt.Sprintf("f%d", a.jobSeq), tab: id, op: op, label: label, folder: folder, dest: dest, state: "planning"}
	v.jobs = append(v.jobs, j)
	a.jobs[j.id] = j

	if op == "delete" {
		remoteDest = ""

		err := a.hub().FilesPlan(context.Background(), j.id, server, op, sources, remoteDest)
		a.Update(func() {
			if err != nil && gen == a.hubGen {
				a.finishJob(j, nil, err.Error())
			}
		})
	}()
	return j
}

// fileNote carries a job on from its notifications. Only a job this app
// planned and still holds moves; files.run and files.list follow only while
// the ready screen shows, and a job planned behind the lock is cancelled
// (plan Decision 1).
func (a *App) fileNote(ev any) {
	switch e := ev.(type) {
	case hubapi.FilesPlanned:
		j := a.jobs[e.ID]
		if j == nil || j.state != "planning" {
			return
		}
		j.planned = &e
		act := model.PlannedAction(j.op, e.Conflicts.Count, j.cancelReq)
		switch {
		case act == "cancel":
			a.filesCancel(j.id) // a cancel sent while planning can be lost: files.done ends it
		case !a.ready(a.hubGen):
			a.cancelLocked(j)
		case act == "confirm":
			j.state = "confirm"
		default:
			a.runJob(j, "skip")
		}
	case hubapi.FilesProgress:
		if j := a.jobs[e.ID]; j != nil && j.state == "running" {
			j.progress = &e
		}
	case hubapi.FilesDone:
		if j := a.jobs[e.ID]; j != nil {
			a.finishJob(j, &e, "")
		}
	}
}

// runJob sends files.run once: the job leaves planning and confirm here.

// folder again if it is still shown (relistAfterJob), only on the ready
// screen: behind the lock the listing stays as it was until Refresh.
func (a *App) finishJob(j *fileJob, d *hubapi.FilesDone, err string) {
	if j.state == "done" {
		return
	}
	j.state, j.done, j.err = "done", d, err
	delete(a.jobs, j.id)

		return
	}

// dropFiles uploads what was dropped on tab id into the folder shown. The
// paths come from the OS, so they are checked here: at most MaxDrop, each
// absolute and present (Electron's grantDropped).
func (a *App) dropFiles(id string, paths []string) {
	v := a.files[id]
	if v == nil || len(paths) == 0 || !a.ready(a.hubGen) || !model.ActionsReady(v.listing, v.loading) {
		return
	}
	if len(paths) > model.MaxDrop {
		v.err = fmt.Sprintf("Drop at most %d items at a time.", model.MaxDrop)
		return
	}
	for _, p := range paths {
		if !filepath.IsAbs(p) {
			v.err = "cannot upload " + p + ": not an absolute path"
			return
		}
		if _, err := os.Lstat(p); err != nil {
			v.err = err.Error()
			return
		}
	}
	a.startJob(id, "upload", paths, v.shown, v.shown, model.JobLabel(baseNames(paths)))
}

// liveFlow runs the app on a copy of the vault src, unlocked with pw. The
// hub keeps your HOME and ssh-agent, as the Electron live specs did (a host
// may log in with the agent); only its runtime directory is a temp one, so
// a running sshgate app is not disturbed.
func liveFlow(t *testing.T, src, pw string) (*flowT, *fakeShell) {
	t.Helper()
	raw, err := os.ReadFile(src)
	if err != nil {
		t.Fatal(err)
	}
	store := filepath.Join(t.TempDir(), "servers.json")
	if err := os.WriteFile(store, raw, 0o600); err != nil {
		t.Fatal(err)
	}
	dir := hubtest.RuntimeDir(t)
	f := flowOn(t, store, append(os.Environ(), "SSHGATE_RUNTIME_DIR="+dir), dir)
	sh := &fakeShell{}
	f.a.Shell = sh
	f.tt.SetSize(1000, 700)
	f.unlockWith(pw)
	return f, sh
}

// ttyPassword reads a line from the terminal with echo off, as
// internal/hub's TestLiveVaultConnect does (stty here: no x/term in app/).
func ttyPassword(t *testing.T, prompt string) string {
	t.Helper()
	tty, err := os.OpenFile("/dev/tty", os.O_RDWR, 0)
	if err != nil {
		t.Skip("no terminal to read the master password from")
	}
	defer tty.Close()
	stty := func(arg string) {
		c := exec.Command("stty", arg)
		c.Stdin = tty
		c.Run()
	}
	fmt.Fprint(tty, prompt)
	stty("-echo")
	line, err := bufio.NewReader(tty).ReadString('\n')
	stty("echo")
	fmt.Fprintln(tty)
	if err != nil {
		t.Fatal(err)
	}
	return strings.TrimRight(line, "\r\n")
}
